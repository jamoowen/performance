## HTTP benchmark reports

The current [interactive HTTP benchmark report](https://jamoowen.github.io/performance/reports/http/comparison.html) and [comparison CSV](https://jamoowen.github.io/performance/reports/http/comparison.csv) are published snapshots. [Campaign findings](docs/reports/http/findings.md) render through GitHub when included in a snapshot.

Refresh the Pages snapshot from the repository root after recording results:

```sh
make publish-report
```

`make compare` still creates local artifacts under `results/http/report/`. `make publish-report` regenerates those artifacts, copies the publishable snapshot into `docs/`, and must be followed by committing and pushing `docs/`; the configured `main`/`docs` GitHub Pages branch then publishes it. `findings.md` is manual campaign notes and is not generated by either command.

Follow-up campaigns publish isolated interactive pages through `make report-suite`. The Pages index links each experiment separately so scheduling, SQLite, memory, framework, and scaling recordings are never mixed in one chart.

Open the [follow-up report index](https://jamoowen.github.io/performance/) after publication.
