Scope and limitations

Service timing starts after routing, body parsing and validation. It includes SQLite work and JSON serialization; it excludes socket transfer and earlier event-loop or kernel scheduling delay.

DB timing includes waiting for serialized SQLite access and SQL work. Rust DB timing also includes the SQLite worker round trip; Python server timings begin inside the worker and exclude the initial thread-pool wait. These timings are not CPU time.

Server timings are available only on successful requests. At overload, compare client latency, failures, goodput, and CPU because failed requests are absent from server-timing percentiles.
