SQLite API capacity search

Single-worker APIs run with one CPU quota and 512 MiB on a shared single-node cluster. Each fresh SQLite database has 5,000 products and a 50% detail, 30% list, 20% stock-write mix. The accepted LAN/Wi-Fi route remains part of every client measurement.

Each adapter has a 30-second warm-up, then 15 seconds of settling/transition and 75 stable seconds per step. RPS starts at 300, 600, 900, 1200, and 1500, then rises by 25%. k6 uses a fixed 1,024 preallocated and maximum measured VUs with a two-second HTTP timeout.

Dropped arrivals were never issued because the fixed VU pool was exhausted. They locate a tested request-path/concurrency boundary, not automatically an API CPU ceiling: assess pod CPU, throttling, and server latency first. Generator guards and recorder failures are inconclusive. This remains an exploratory boundary search, not a universal server maximum.
